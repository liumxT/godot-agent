# 运维手册（Runbook）

> 文档目的：为安装、升级、恢复、安全事件与长期运行提供可执行处置步骤。
> 适用范围：产品管理员、支持工程师与发布负责人。
> 最后更新：2026-11-27（E12-T17）。

## 1. 通用原则

1. 先保留证据，再执行修复：导出支持包、记录 `correlation_id` 与时间窗口。
2. 不删除用户项目与用户数据；恢复与删除都必须显式确认。
3. 状态为 `UNKNOWN` 时先核实，不把未知当作成功或失败。
4. 变更类操作只允许 admin 客户端执行，且全部写入产品审计。
5. 数据库操作前先创建恢复点或备份。

## 2. 安装失败（`INSTALL_PRECHECK_FAILED`）

1. 在安装界面查看失败检查项：目录隔离、组件完整性、写权限、磁盘空间。
2. 目录隔离失败：数据目录不得位于安装目录内部，改为同级或独立目录。
3. 写权限失败：以有权限的账户运行安装器，或改用可写目录。
4. 磁盘空间不足：清理到至少 2 GB 可用空间。
5. 重新执行预检查；连续失败时导出诊断信息并附带安装步骤记录。

安装验证阶段失败会进入 `PARTIAL` 或 `RECOVERY_REQUIRED`，按第 5 节处理。

## 3. 更新失败

### 3.1 签名无效（`UPDATE_SIGNATURE_INVALID`）

1. 确认更新清单来自官方通道，且 `package_hash` 为 `sha256:` 加 64 位十六进制。
2. 校验签名密钥版本与产品内置公钥一致；签名缺失与签名不匹配都禁止安装。
3. 不要关闭签名校验或手工修改清单；联系发布负责人重新签发。

### 3.2 未批准（`UPDATE_NOT_APPROVED`）

1. 更新必须由用户显式批准；自动更新只能下载与暂存。
2. 在更新页面确认版本、变更说明与影响范围后批准。
3. 若批准后清单内容变化，批准自动失效，需要重新批准。

### 3.3 降级与通道

- 目标版本低于当前版本时拒绝安装。
- `DEV` / `BETA` / `STABLE` 互不混用；从测试通道回到稳定通道需显式切换。

## 4. 数据库迁移失败（`MIGRATION_BACKUP_MISSING` / `RECOVERY_REQUIRED`）

1. 停止写入：暂停 Agent 任务与构建，避免继续产生新数据。
2. 查看迁移记录：`product_migrations` 与 `product_migration_runs` 的状态和失败原因。
3. 确认备份存在且校验通过；缺少备份时禁止重试迁移。
4. 优先按第 5 节从迁移前恢复点恢复，再使用匹配 schema 的产品版本启动。
5. schema 高于产品支持版本时不得启动旧版本，防止降级写入。
6. 修复后在预发布环境复跑同一迁移并记录结果。

## 5. 恢复流程

1. **检测**：启动时若发现未完成安装、更新或迁移，产品进入 `RECOVERY_DETECTED`。
2. **状态检查**：读取安装、更新、迁移、恢复点与外部区域状态。
   外部区域无法探测时标记 `UNKNOWN`。
3. **生成计划**：计划包含恢复点、受影响区域、是否保留用户数据与是否删除项目。
   任何 `UNKNOWN` 都会要求人工核实。
4. **用户确认**：确认前不得执行。确认内容包含恢复点哈希与影响范围。
5. **执行**：按 `DATABASE` / `CONFIG` / `PLUGIN` / `FULL` 执行；先停止事件派发，
   保护现有数据库副本，再恢复并校验。
6. **验证**：检查安装记录计数、schema 版本与健康状态；失败进入
   `RECOVERY_FAILED` / `PARTIAL_RECOVERY` / `MANUAL_INTERVENTION_REQUIRED`。
7. 全过程写入产品审计，保留恢复点与校验和。

## 6. 数据库损坏（`DATABASE_CORRUPTED`）

1. 立即停止后端，复制 `data/` 目录作为现场证据。
2. 运行完整性检查（`PRAGMA integrity_check`）。
3. 从最近可用备份恢复；恢复前确认 WAL/SHM 文件一并处理。
4. 恢复后启动并检查 `/api/v1/product/health` 与 `/health/ready`。
5. 若备份不可用，保留原库并升级为人工介入，不要重建空库覆盖现场。

## 7. 协议不兼容（`PROTOCOL_INCOMPATIBLE`）

1. 对比产品组件中的 `api_protocol` 与 Godot 插件声明版本。
2. 主版本不一致：升级插件或后端到匹配版本，不允许强行连接。
3. 次版本不一致：允许连接但记录警告；验证关键工具调用。
4. 更新兼容性矩阵与发布说明。

## 8. 凭据存储不可用（`SECRET_STORE_UNAVAILABLE`）

1. 确认系统凭据库可用（Windows Credential Manager / macOS Keychain / Secret Service）。
2. 不可用时产品会明确警告；不得改用明文文件保存密钥。
3. 可临时使用环境变量引用（`env://` / `${VAR}`），并在修复后迁回凭据库。
4. 轮换受影响的密钥，并检查审计日志是否存在异常读取。

## 9. 模型不可用（`MODEL_UNAVAILABLE`）

1. 查看 Provider 配置与模型注册状态。
2. 显式选择已注册且能力匹配的模型；系统不会静默降级。
3. 检查配额、网络与 API Key 是否有效。
4. 若模型已下线，登记替代模型并更新 Agent Model Policy。

## 10. 安全事件

1. 立即撤销受影响客户端与 Session，撤销相关 License 能力。
2. 保留审计日志、支持包与网络日志；不要修改现场。
3. 轮换 API Key、签名密钥与客户端密钥。
4. 评估影响范围：项目访问、工具执行、发布与分发。
5. 按事件等级通知负责人，并记录处置时间线。
6. 复盘后补充测试与策略规则。

## 11. 支持包与崩溃报告

1. 支持包默认脱敏：密钥、Token、绝对路径与超长字段会被替换或截断。
2. 导出需要显式确认；包内包含产品版本、组件、健康检查、日志摘要与最近审计。
3. 支持包不包含项目源码与资源；如确需附加，单独征得用户同意。
4. 崩溃报告默认仅本地保存（`LOCAL_ONLY`），不会自动上传。

## 12. 长期运行与容量

1. 监控数据库大小、日志目录、备份目录与支持包目录。
2. 备份按保留策略清理；迁移前备份不得在验证前删除。
3. 事件 Outbox/Inbox 积压持续增长时检查派发器与消费者。
4. 定期执行恢复演练（建议每季度），记录恢复时间与校验结果。
5. 长时间运行的 Agent 任务需要预算与超时；中断后按恢复协调器处理。

## 13. 发布与撤回

1. 发布候选必须包含 7 类证据：单元、集成、Godot 插件、兼容性矩阵、
   安装冒烟、安全扫描与回滚演练。
2. 候选必须签名并生成 SBOM；缺少任一项禁止审批。
3. 审批绑定产物哈希；内容变化后审批失效。
4. 发布后验证哈希与健康检查；异常时按第 5 节回滚并标记撤回。

## 14. 支持周期与下线

1. 维护窗口与支持版本在发布说明中声明。
2. 终止支持前至少提前一个发布周期通知，并提供升级路径。
3. 下线版本不再接收更新清单签名；保留历史清单用于审计。
4. 用户数据与项目文件的删除只能由用户显式发起。
