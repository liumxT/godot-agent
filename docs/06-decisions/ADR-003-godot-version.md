# ADR-003：Godot 版本基线

- **状态：** Accepted
- **决策日期：** 2026-11-17
- **决策人：** 项目负责人
- **相关文档：** [E0-T02](../../完整开发计划细分/E0.md)、[实施蓝图 §9/§17](../../实施蓝图.md)、[README 环境清单](README.md)

## 1. 背景与问题

Godot 版本决定：插件可用的 Editor API、`.tscn/.tres` 的格式解析、
headless 导出命令、以及所有集成测试的执行环境。
本项目不是"用 Godot 做游戏"，而是**深度操作编辑器**（`EditorPlugin`、`EditorInterface`、
`UndoRedo`、Dock 面板、文件系统同步、headless 构建），因此必须锁定窄范围的基线，
而不是宣称"支持 Godot 4 全版本"。

## 2. 环境事实（本机实测）

| 项 | 实测值 |
| --- | --- |
| 可执行文件 | `D:\应用程序\godot\Godot_v4.5.1-stable_win64.exe\Godot_v4.5.1-stable_win64_console.exe` |
| 版本字符串 | `4.5.1.stable.official.f62fdbde1` |
| 编辑器配置 | `%APPDATA%\Godot\editor_settings-4.5.tres` |
| 已有工程 | `first_2d`、`test`、`tps-demo`、`platformer`、`fishing-game`（均为 4.5 下创建/使用） |
| 导出模板 | `%APPDATA%\Godot\export_templates` 为空 |
| 发行版类型 | 标准版（非 .NET），因此不内置 C# 运行时 |

## 3. 比较标准

| 标准 | 说明 |
| --- | --- |
| 与现有环境/工程一致 | 避免为平台开发先升级用户工程 |
| Editor API 稳定性 | 插件 API 跨 minor 存在行为变更 |
| 必要能力可用性 | `TileMapLayer`（4.3+）、`EditorUndoRedoManager`、`WebSocketPeer` |
| 回归面 | 每多支持一个 minor，`.tscn` 与 Editor 行为回归面近似翻倍 |
| headless 可测试性 | CI 需要固定版本执行导出与冒烟 |

## 4. 备选方案

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A 保守 | 4.5.1 基线，已知环境一致 | **采纳** |
| B 激进 | 升级到最新 4.7.x 作为基线 | 需先升级现有工程并重新验证插件/格式，收益不足 |
| C 宽兼容 | 同时全量支持 4.5–4.7 | 测试成本与回归风险不可控 |

## 5. 决策

| 项 | 决策 |
| --- | --- |
| 开发与测试基线 | **Godot 4.5.1**（精确到 patch，CI/本地/集成测试统一） |
| 承诺支持范围 | `4.5.x`（主支持）；`4.6+` 仅在冒烟级别 best-effort，不承诺 |
| 拒绝范围 | `< 4.5` 直接拒绝：插件启动时用 `Engine.get_version_info()` 校验并给出明确提示 |
| 脚本语言 | 仅 GDScript；**不解析、不生成 C#** |
| 发行版 | 标准版（非 .NET） |
| 渲染器 | Compatibility（2D 优先、机器覆盖面广、headless 稳定） |
| 3D | 首期不支持，架构预留 |
| 导出模板 | 必须安装 4.5.1 对应版本（当前缺失） |

附加约束：

1. 插件不得使用高于 4.5 的 API；若必须使用新 API，需特性检测并提供降级路径。
2. 所有 `.tscn/.tres` 解析以 4.5 格式为准，读取时保留未知字段，写回时不得丢弃。
3. 插件不得把本地密钥、后端 token 写入项目目录（蓝图 §3.3）。
4. 端到端验证必须使用真实 4.5.1 编辑器/Runtime，不接受 Mock 替代全部链路。

## 6. 选择理由

1. 与已有 5 个真实工程、编辑器配置、导出环境完全一致，避免"为平台先升级工程"的额外成本与风险。
2. 4.5.1 已具备 MVP 所需的全部能力（TileMapLayer、EditorInterface、UndoRedo、WebSocketPeer、headless 导出）。
3. 窄范围支持把 `.tscn` 格式与 Editor 行为回归面限制在可控区间，符合蓝图"Evidence Driven / Auditable"原则。
4. 后续升级到 4.6/4.7 是一次独立的、可验证的版本迁移，而不是长期背负多版本兼容。

## 7. 影响范围

| 影响项 | 说明 |
| --- | --- |
| E0-T04 | 插件骨架按 4.5 API 编写，`plugin.cfg` 声明版本约束 |
| E3 | Editor Bridge / Runtime Bridge 只在 4.5.1 上验收 |
| E9/E10 | headless 测试与导出固定使用同一 4.5.1 可执行文件 |
| 用户工程 | 低于 4.5 的工程不支持，需在文档中明确 |
| 导出能力 | 模板缺失将阻塞 E10，需提前安装 |

## 8. 迁移要求

未来升级基线时（例如 4.7）：

1. 先建立 4.7 的独立 CI 任务，不改动 4.5 任务。
2. 用 `platformer` 与 `fishing-game` 做回归：扫描、修改、运行、导出四项全部通过。
3. 记录 `.tscn` 差异清单，确认解析器不需要破坏性调整。
4. 通过后修订本 ADR，再切换主基线。

## 9. 变更条件

- 4.5.x 出现阻塞性缺陷且无法规避。
- 目标用户主流工程普遍升级到更新 minor。
- 新版本提供本平台必需、且无法在 4.5 降级实现的能力。
