# ADR-005：本地通信机制

- **状态：** Accepted
- **决策日期：** 2026-11-17
- **决策人：** 项目负责人
- **相关文档：** [ADR-002](ADR-002-backend-framework.md)、[E0-T05](../../完整开发计划细分/E0.md)、[实施蓝图 §8](../../实施蓝图.md)、[错误码规范](../03-development/errors.md)

## 1. 背景与问题

Godot 编辑器插件（GDScript）与本地 Backend（Python）需要双向通信：

- 插件 → 后端：命令请求（扫描、修改、生成、执行任务），需要明确的响应与错误码。
- 后端 → 插件：任务进度、状态事件、需要用户确认的操作，需要实时推送。
- 诊断与 CI：需要无需会话即可探测服务是否存活。

通信只发生在同一台机器，不允许暴露到局域网或公网。

## 2. 比较标准

| 标准 | 说明 |
| --- | --- |
| Godot 原生支持 | 优先使用 `WebSocketPeer` 等内置能力，避免自写协议 |
| 双向与实时性 | 需要服务端主动推送事件 |
| 可测试性 | CI 中可无 GUI 验证 |
| 跨平台 | Windows / macOS / Linux 一致 |
| 安全边界 | 仅回环、可鉴权、可限流 |
| 调试成本 | 可用标准工具（curl、日志）排查 |

## 3. 备选方案

| 方案 | 评价 |
| --- | --- |
| **WebSocket（主）+ HTTP（健康/诊断）** | Godot 原生支持、双向、可携带 JSON 契约；HTTP 便于存活探测 |
| 仅 HTTP 轮询 | 实现简单，但事件延迟高、连接语义弱 |
| 命名管道 / Unix Socket | 平台差异大，GDScript 无原生支持 |
| gRPC | 需要额外运行时与代码生成，Godot 侧集成成本高 |
| stdio 子进程 | 生命周期与 Backend 独立运行冲突，不适合常驻服务 |

## 4. 决策

| 项 | 决策 |
| --- | --- |
| 主通道 | WebSocket，路径 `/ws`，承载请求/响应与事件 |
| 辅助通道 | HTTP：`GET /health`（存活）、后续诊断接口 |
| 绑定地址 | 仅 `127.0.0.1`（或 `::1`），端口默认 `8765` |
| 消息格式 | JSON，遵循 `packages/contracts/`（协议版本 `1.0`） |
| 关联标识 | 每请求 `request_id`，跨进程 `correlation_id`，事件 `event_id` |
| 错误 | 统一错误体（`error.schema.json`）+ 大写蛇形错误码 |
| 投递语义 | 事件 At-least-once，接收方按 `event_id` 去重 |
| 认证 | 本地 token + 会话租约（E2 定义细节，E0 只保留契约字段） |
| 心跳与重连 | 心跳、断线重连、会话恢复由 E3 实现 |

## 5. 选择理由

1. `WebSocketPeer` 是 Godot 内置能力，插件不需要引入第三方网络库。
2. WebSocket 同时覆盖命令响应与事件推送，避免 HTTP 轮询带来的延迟与状态管理复杂度。
3. 保留 HTTP 健康检查，使 CI、安装器与用户可快速判断服务状态，不必建立会话。
4. 仅回环绑定 + token 鉴权，把攻击面限制在本机进程。

## 6. 影响范围

| 影响项 | 说明 |
| --- | --- |
| E0-T05 | 请求/响应/事件/错误契约按本 ADR 的通道设计 |
| E2 | 认证握手、token 存储与租约实现 |
| E3 | 心跳、重连、背压与编辑器侧连接管理 |
| E0-T08 | 日志统一使用 `request_id` / `correlation_id` |
| CI | 健康检查接口可直接被脚本与 workflow 探测 |

## 7. 变更条件

- 出现大体积二进制传输（纹理、音频）导致 JSON/WebSocket 不可接受的场景，
  届时评估独立二进制通道，而非替换主协议。
- 需要局域网内多机协作（当前产品前提不允许）。
- Godot 侧 WebSocket 实现出现无法规避的缺陷。

## 8. 尚未冻结的细节

端口是否允许用户修改（E2 配置项）、消息大小上限与分片策略（E3）、
背压与队列上限（E3）、token 轮换周期（E2）。
