# ADR-004：Primary Database

- **状态：** Accepted
- **决策日期：** 2026-11-17
- **决策人：** 项目负责人
- **相关文档：** [ADR-002](ADR-002-backend-framework.md)、[E0-T06](../../完整开发计划细分/E0.md)、[数据库规范](../03-development/database.md)、[实施蓝图 §7](../../实施蓝图.md)

## 1. 背景与问题

本项目是**本地优先**的单机工具：每个用户运行自己的 Backend，数据量在项目级
（任务、事件、资产记录），并发写入来自编辑器插件与后台 Worker。
需要同时满足：事务一致性、可审计迁移、可备份恢复、零运维安装。

## 2. 比较标准

| 标准 | 说明 |
| --- | --- |
| 零安装 | 用户机器上不额外部署数据库服务 |
| 事务与约束 | 需要 ACID、外键、唯一约束 |
| 迁移能力 | 结构变更可版本化、可回滚 |
| 并发模型 | 单进程多协程写入，允许单写者 |
| 备份/恢复 | 用户可自行备份，升级前可自动备份 |
| 打包体积 | 影响 PyInstaller 产物 |
| 跨平台 | Windows / macOS / Linux 行为一致 |

## 3. 备选方案

| 方案 | 评价 |
| --- | --- |
| **SQLite（WAL）** | 单文件、零运维、事务完整、Alembic 支持成熟；单写者需短事务约束 |
| PostgreSQL | 能力过剩，需要用户安装/维护服务，违背本地零安装 |
| DuckDB | 分析型负载优秀，OLTP 与并发写、约束能力弱于 SQLite |
| JSON / 自定义文件 | 无事务与迁移，损坏后难恢复 |
| LMDB / RocksDB | 键值模型，无 SQL/外键/迁移生态，查询需自建 |

驱动备选：`aiosqlite`（选，配合 SQLAlchemy async）、同步 `sqlite3`（阻塞事件循环）、
`sqlcipher`（加密需求未确认，暂不引入）。

## 4. 决策

| 项 | 决策 |
| --- | --- |
| 主库 | **SQLite 单文件**，位于用户数据目录 `data_dir/backend.db` |
| 访问层 | SQLAlchemy 2.0 async 引擎 + `aiosqlite` |
| 迁移 | Alembic，迁移文件入仓，编号 `00000x_name` |
| 连接参数 | `journal_mode=WAL`、`synchronous=NORMAL`、`foreign_keys=ON`、`busy_timeout=5000` |
| 事务 | 短事务；一个事务只覆盖一次业务写入；禁止跨模块长事务 |
| 并发 | 单写者；读多写少；写冲突依赖 `busy_timeout` 重试 |
| 备份 | 升级前用 SQLite 在线备份 API 生成 `backups/<name>-<UTC>.db` |
| 模块隔离 | 每个模块只通过自己的 Repository 访问本模块数据 |
| 跨模块一致性 | Outbox/Inbox + At-least-once，消费方按幂等键去重（E1/E4 实现） |
| 运行时建表 | 禁止；只允许 Alembic 迁移建表 |

## 5. 选择理由

1. 与"用户零安装、数据留在本机"的产品前提一致，备份就是一个文件。
2. WAL + 短事务足以覆盖单用户编辑器的写入频率，避免引入服务进程。
3. Alembic 让结构变更可审计、可回滚，满足 E0-T06 的迁移要求。
4. 在线备份 API 可以在不中断服务的情况下保证升级前有可用副本。

## 6. 影响范围

| 影响项 | 说明 |
| --- | --- |
| E0-T06 | 已落地 engine/PRAGMA/迁移/备份与失败包装 |
| E1+ | 模块 Repository 的写法、幂等键设计受本 ADR 约束 |
| E10 | 打包需包含 SQLite 动态库（Windows 使用 Python 内置） |
| 运维 | 用户需理解"备份文件"而非"数据库服务" |

## 7. 变更条件

- 出现多进程/多用户同时写同一库的真实需求。
- 单写者导致可观测的写阻塞（先在压测下评估 WAL 调优与写入合并）。
- 需要跨机器同步或服务端部署（届时评估 PostgreSQL）。

## 8. 尚未冻结的细节

加密需求（若确认，另行评估 SQLCipher，不改变本 ADR 的主库选型）。
