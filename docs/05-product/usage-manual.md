## 1. 快速开始

### 1.1 这是什么

Godot AI Agent Platform 在 Godot 编辑器旁运行一个本地后端，通过 AI Agent 帮助你完成游戏开发任务：编写脚本、生成场景、处理资产、验证代码、构建发布。

核心原则：
- **安全**：AI 写操作必须经你审批，不会静默修改项目
- **隔离**：每个项目、每个会话独立授权
- **可追溯**：所有 AI 操作留下审计与证据链
- **可恢复**：安装、更新、迁移失败均可回滚

### 1.2 最快上手（5 步）

1. **安装后端**：运行安装包，选择安装目录与数据目录（必须分离）
2. **完成首次向导**：配置模型 Provider 与 API Key
3. **安装插件**：在 Godot 中启用 `Godot AI Agent` 插件
4. **连接项目**：打开 Godot 项目，点击插件面板的"连接后端"
5. **创建任务**：在任务面板描述需求，Agent 开始工作

### 1.3 系统要求

| 项 | 最低 | 推荐 |
| --- | --- | --- |
| 操作系统 | Windows 10 x86_64 | Windows 11 x86_64 |
| Godot | 4.4 | 4.5.1 |
| 磁盘 | 2 GB 可用 | 10 GB 可用 |
| 内存 | 8 GB | 16 GB |
| 网络 | 配置在线模型时需要 | 稳定网络 |

## 2. 安装与首次运行

### 2.1 安装步骤

1. 关闭正在运行的 Godot 编辑器
2. 运行安装包：`GodotAIAgent-Setup-1.0.0.exe`（Windows）
3. 选择**安装目录**（程序文件位置）
4. 选择**数据目录**（数据库、配置、日志位置）—— 必须与安装目录分离，数据目录不能在安装目录内部
5. 安装器执行预检查：
   - 组件完整性（11 个组件全部存在）
   - 目录隔离（安装目录 ≠ 数据目录）
   - 写权限（数据目录可写）
   - 磁盘空间（≥ 2 GB）
6. 预检查通过后开始复制文件，每一步状态可追踪
7. 安装完成后启动产品

### 2.2 目录结构

```
<安装目录>/
  backend/            # 后端可执行文件
  godot_plugin/       # Godot 插件
  documentation/      # 文档
  uninstall.exe       # 卸载程序

<数据目录>/
  config/             # 分层配置
  data/               # 数据库与备份
    godot_ai_agent.db # SQLite 数据库
    backups/          # 数据库备份
  logs/               # 日志
  support-bundles/    # 诊断支持包
```

默认数据目录：
- Windows：`%LOCALAPPDATA%\GodotAIAgent`
- Linux：`$XDG_DATA_HOME/godot-ai-agent`

### 2.3 首次运行向导（12 步）

首次启动依次引导：

1. **欢迎与许可协议** — 阅读并同意
2. **选择数据目录** — 确认或修改数据目录
3. **初始化数据库** — 创建数据库，显示 schema 版本（`000033`）
4. **健康检查** — 后端、数据库、迁移状态
5. **配置凭据存储** — 系统凭据库（不可用时警告，不静默降级）
6. **选择模型 Provider** — OpenAI / Anthropic / 本地
7. **配置 API Key** — 保存为 `cred://` 引用，不回显明文
8. **选择默认模型** — 不可用时直接报错，不自动切换
9. **设置预算** — Token / 成本 / 时长上限
10. **检测 Godot 版本** — 验证兼容性
11. **安装 Godot 插件** — 复制插件到项目
12. **连接项目目录** — 选择你的 Godot 项目

> ⚠️ 凭据缺失、模型不可用、项目不可写都会阻止继续。任一步可返回上一步。

### 2.4 验证安装

安装完成后，可通过以下方式验证：

- 访问 `http://127.0.0.1:8765/api/v1/product/info`（需认证）
- 访问 `http://127.0.0.1:8765/health/ready`（健康检查）
- Godot 插件面板显示"已连接"

## 3. 连接 Godot 项目

### 3.1 启用插件

1. 打开 Godot 项目
2. 进入 `项目 → 项目设置 → 插件`
3. 启用 `Godot AI Agent`
4. 编辑器右侧出现 `AI Agent` 面板

### 3.2 连接后端

1. 在 `AI Agent` 面板点击"连接后端"
2. 后端地址默认 `http://127.0.0.1:8765`，可修改
3. 连接成功后显示：
   - 认证状态：已认证
   - Session ID：当前会话
   - 项目身份：当前 Godot 项目

### 3.3 项目隔离

- 一个编辑器会话只绑定**一个项目**
- 项目身份由 Godot 工程文件（`project.godot`）确定
- 切换项目需要新建会话
- 旧会话的权限不会跨项目复用
- 所有 AI 操作的授权范围限定在当前项目

## 4. 模型与 Provider 配置

### 4.1 支持的 Provider

| Provider | 说明 | 所需凭据 |
| --- | --- | --- |
| OpenAI | GPT 系列模型 | `OPENAI_API_KEY` |
| Anthropic | Claude 系列模型 | `ANTHROPIC_API_KEY` |
| 本地 | 兼容 OpenAI API 的本地模型 | 本地地址 |

### 4.2 配置 Provider

在"模型配置"页面：
1. 选择 Provider 类型
2. 输入 API Key（保存为 `cred://` 引用，明文会被拒绝）
3. 注册可用模型列表
4. 选择默认模型

> ⚠️ 模型不可用时直接报错，**不会自动切换到其他模型**。请确保选择的模型已注册且可用。

### 4.3 模型选择规则

- 必须显式选择已注册的模型
- 模型能力必须匹配任务需求（如多模态任务需要多模态模型）
- 模型下线后需重新登记替代模型并更新 Agent 配置

## 5. 任务与 Agent 协作

### 5.1 创建任务

在任务面板：
1. 填写**任务目标**（描述你想要的结果）
2. 填写**验收标准**（如何判断任务完成）
3. 选择任务类型（脚本开发 / 场景构建 / 资产处理 / 验证 / 其他）
4. 设置优先级与截止时间（可选）
5. 提交任务

### 5.2 Agent 工作流程

```
你提交任务
   ↓
Agent 读取项目上下文（当前项目的文件、场景、配置）
   ↓
Agent 制定执行计划（步骤分解）
   ↓
Agent 调用工具执行（只读工具直接执行，写操作生成 ChangeSet）
   ↓
你审批 ChangeSet（查看差异、风险、影响范围）
   ↓
批准后写入项目
   ↓
Agent 继续后续步骤
   ↓
任务完成（满足验收标准）
```

### 5.3 查看任务进度

- 任务面板显示状态：`QUEUED` / `RUNNING` / `WAITING_APPROVAL` / `BLOCKED` / `COMPLETED` / `FAILED`
- 可查看 Agent 的计划、已执行步骤、当前步骤
- 可暂停、恢复、取消任务

### 5.4 会话管理

- 每个编辑器连接创建一个 Session
- Session 有过期时间，过期后需重新连接
- 可在"会话管理"页面查看所有活跃会话

## 6. 工具调用与权限

### 6.1 工具风险等级

| 风险等级 | 示例工具 | 默认行为 |
| --- | --- | --- |
| R0 | 读取配置、查询状态 | 自动允许 |
| R1 | 读取项目文件 | 允许（需项目访问权限） |
| R2 | 写入文件、修改场景 | 生成 ChangeSet，需审批 |
| R3 | 运行命令、导出项目 | 需人工审批 |
| R4 | 删除文件、发布产物 | 需强审批 |

### 6.2 内置工具

- **文件工具**：读取、写入、重命名项目文件
- **Godot 工具**：场景操作、节点操作、资源导入
- **搜索工具**：在项目中搜索代码、资源
- **命令工具**：运行受限命令（需审批）
- **验证工具**：触发静态检查、运行时验证

### 6.3 自定义工具

可在"工具管理"页面注册自定义工具：
- 声明工具名称、版本、JSON Schema
- 声明风险等级
- 写工具必须经 ChangeSet，R3+ 必须审批

## 7. 变更集与审批

### 7.1 什么是 ChangeSet

ChangeSet 是 AI 提议的一组变更，包含：
- 变更的文件列表（新增 / 修改 / 删除）
- 每个文件的差异（diff）
- 变更原因与上下文
- 风险等级评估
- 影响范围分析

### 7.2 审批流程

1. Agent 执行写操作 → 生成 ChangeSet（状态 `READY_FOR_APPROVAL`）
2. 你在审批面板查看：
   - 文件差异（逐行对比）
   - 风险等级（低 / 中 / 高）
   - 影响范围（受影响的场景、脚本、资产）
   - 变更原因
3. 选择：
   - **批准**：变更写入项目
   - **拒绝**：变更被丢弃，Agent 收到反馈
   - **要求修改**：Agent 根据反馈重新生成

### 7.3 批量审批

- 多个相关 ChangeSet 可批量审批
- 高风险变更必须逐个审批
- 审批记录全部写入审计日志

## 8. 多 Agent 协作

### 8.1 Agent 角色

平台支持多种专业 Agent 协作：

| Agent 类型 | 职责 |
| --- | --- |
| Lead Agent | 任务分解、协调、汇总 |
| 程序员 Agent | 编写 GDScript / C# 脚本 |
| 场景设计师 Agent | 构建场景、节点树 |
| 资产 Agent | 处理图像、音频、3D 资源 |
| 验证 Agent | 执行验证与质量检查 |
| 构建 Agent | 构建、打包、发布 |

### 8.2 团队协作

1. 创建任务时可选择"多 Agent 协作"模式
2. Lead Agent 分解任务，分配给专业 Agent
3. Agent 之间通过消息通信
4. 冲突自动检测与解决（资源竞争、变更冲突）
5. 共享上下文，避免重复工作

### 8.3 预算管理

- 可设置团队级预算（Token / 成本 / 时长）
- 超预算自动暂停任务
- 可查看每个 Agent 的消耗明细

## 9. 资产管线

### 9.1 资产导入

1. 在资产面板选择"导入资产"
2. 选择源文件（图像 / 音频 / 3D 模型）
3. AI 自动处理：
   - 格式转换
   - 压缩优化
   - 元数据提取
   - 质量检查
4. 处理完成后生成 ChangeSet，审批后导入项目

### 9.2 资产版本管理

- 每个资产保留版本历史
- 可回滚到任意版本
- 版本差异可视化
- 资产来源可追溯（记录生成 Provider、参数、时间）

### 9.3 质量控制

AI 对生成的资产自动检查：
- 图像：分辨率、格式、文件大小
- 音频：采样率、时长、音量
- 3D：面数、UV、法线
- 不合格资产标记为 WARNING 或 FAILED

## 10. 验证与 QA

### 10.1 验证类型

| 层级 | 验证内容 |
| --- | --- |
| 静态验证 | 语法检查、Lint、类型检查 |
| 结构验证 | 场景结构、节点树完整性 |
| 资源验证 | 资产引用完整性、缺失资源检测 |
| 运行时验证 | 运行游戏检查错误、崩溃 |
| 视觉验证 | 截图对比、UI 一致性 |
| 性能验证 | FPS、加载时间、内存占用 |

### 10.2 触发验证

- 在"验证中心"手动触发
- 任务完成后自动触发
- 构建前自动触发
- 可配置 CI 自动验证

### 10.3 验证证据

- 每项验证都产生证据（日志、截图、指标）
- 没有证据的"通过"不算通过
- 验证结果可追溯到具体版本

## 11. 构建与发布

### 11.1 构建项目

1. 在"构建"页面选择构建配置
2. 选择目标平台（Windows / Linux / macOS / Web / 移动）
3. 选择导出预设
4. 触发构建
5. 构建使用固定 Godot 版本，确保可复现

### 11.2 构建产物

- 产物不可变（内容哈希固定）
- 相同内容幂等（重复构建不产生新版本）
- 不同内容生成新版本
- 每个产物带签名与哈希

### 11.3 发布流程

1. 创建发布候选（Release Candidate）
2. 必须包含 7 类证据：
   - 单元测试通过
   - 集成测试通过
   - Godot 插件测试通过
   - 兼容性矩阵验证
   - 安装冒烟测试通过
   - 安全扫描通过
   - 回滚演练通过
3. 候选必须签名 `SIGNED` 并生成 SBOM
4. admin 审批后才能发布
5. 发布绑定产物哈希，内容变化后审批失效

## 12. 配置管理

### 12.1 四层配置

```
SYSTEM_DEFAULT（最低） < USER_GLOBAL < PROJECT_OVERRIDE < SESSION_OVERRIDE（最高）
```

| 层级 | 范围 | 示例 |
| --- | --- | --- |
| SYSTEM_DEFAULT | 全局默认 | 默认模型、默认端口 |
| USER_GLOBAL | 当前用户所有项目 | 用户偏好的主题 |
| PROJECT_OVERRIDE | 单个项目 | 项目专属模型配置 |
| SESSION_OVERRIDE | 当前会话 | 临时调试配置 |

### 12.2 受保护配置

以下配置项不可被低优先级覆盖：
- `security.*`（安全相关）
- `permissions.*`（权限相关）
- `privacy.telemetry_default`（遥测默认）
- `update.require_signature`（更新签名要求）
- `update.require_user_approval`（更新用户批准）
- `agent.install_allowed`（Agent 安装权限）

### 12.3 敏感值规则

API Key、Token 等敏感值**只能**使用以下引用格式：

| 格式 | 说明 |
| --- | --- |
| `cred://<name>` | 系统凭据库 |
| `secret://<name>` | 密钥管理服务 |
| `keyring://<name>` | 系统 Keyring |
| `env://<VAR>` | 环境变量 |
| `${ENV_VAR}` | 环境变量插值 |

> ⚠️ 明文密钥会被拒绝保存。导出配置时自动脱敏密钥与绝对路径。

### 12.4 导出配置

- 导出时自动脱敏：密钥 → `<redacted>`，绝对路径 → `<path>`
- 不包含项目源码与资源
- 可用于迁移、备份或技术支持

## 13. 隐私与数据

### 13.1 遥测

- **默认关闭**
- 开启必须显式选择类别：
  - 崩溃报告
  - 使用统计
  - 性能数据
- 可随时关闭，关闭后不再收集

### 13.2 数据收集范围

发送给模型的上下文**不包含**：
- 项目源码（除非你明确允许）
- 项目资源文件
- 绝对路径（被替换为相对路径）
- 密钥 / Token（被脱敏）

### 13.3 上下文预览

在发送给模型前，可预览将被发送的内容：
- 确认不包含敏感信息
- 确认不包含不该发送的项目内容
- 预览不实际发送，仅检查

### 13.4 删除数据

- 可删除遥测与诊断记录
- **不会**删除项目文件
- **不会**删除用户数据
- 删除需显式确认（两次确认）

## 14. 升级、备份与恢复

### 14.1 检查更新

- 更新通道：`DEV`（开发版）/ `BETA`（测试版）/ `STABLE`（稳定版，默认）
- 更新清单必须带签名与 SHA-256
- 以下情况禁止安装：
  - 签名无效
  - 哈希不符
  - 版本低于当前（降级被禁止）
  - 缺少必要字段
- 安装前必须显式批准

### 14.2 数据库迁移

- 升级前**强制**创建备份
- 备份路径写入迁移记录
- 迁移失败 → 进入 `RECOVERY_REQUIRED` 状态
- schema 高于产品支持版本 → 阻止启动（防止降级写入）

### 14.3 备份

- 数据库自动备份（升级前、定时）
- 备份位置：`<数据目录>/data/backups/`
- 备份带校验和，恢复前验证

### 14.4 恢复

恢复点类型：

| 类型 | 恢复内容 |
| --- | --- |
| 数据库 | 数据库回滚到某个时间点 |
| 配置 | 配置回滚 |
| 插件 | 插件版本回滚 |
| 完整 | 以上全部 |

恢复流程：
1. 检测到异常 → 进入恢复流程
2. 检查状态（安装、更新、迁移、外部区域）
3. 生成恢复计划
4. **需人工确认**（无法确认的状态标记 `UNKNOWN`，必须人工核实）
5. 执行恢复
6. 验证恢复结果

> ⚠️ 恢复**保留用户数据**，**不删除项目文件**。

### 14.5 卸载

- 卸载默认保留用户数据、项目与日志
- 卸载**不会**删除任何 Godot 项目文件
- 需清理数据时，在"隐私与数据"页面单独确认

## 15. 诊断与技术支持

### 15.1 健康检查

访问产品健康状态：
- `GET /api/v1/product/health` — 产品整体健康
- `GET /health/ready` — 就绪检查
- `GET /health/live` — 存活检查

健康检查项：
- 数据库连接
- 数据库 schema 版本
- 安装状态
- License 状态
- 未完成操作（更新 / 迁移 / 恢复）

### 15.2 错误码目录

产品内建 9 个标准错误码，每个关联恢复步骤：

| 错误码 | 说明 |
| --- | --- |
| INSTALL_PRECHECK_FAILED | 安装预检查失败 |
| UPDATE_SIGNATURE_INVALID | 更新签名无效 |
| UPDATE_NOT_APPROVED | 更新未批准 |
| MIGRATION_BACKUP_MISSING | 迁移备份缺失 |
| DATABASE_CORRUPTED | 数据库损坏 |
| PROTOCOL_INCOMPATIBLE | 协议不兼容 |
| SECRET_STORE_UNAVAILABLE | 凭据存储不可用 |
| MODEL_UNAVAILABLE | 模型不可用 |

### 15.3 支持包

需要技术支持时：
1. 进入"诊断"页面
2. 点击"生成支持包"
3. 确认导出（支持包会被脱敏）
4. 将支持包发送给技术支持

支持包包含：
- 产品版本与组件信息
- 健康检查结果
- 日志摘要
- 最近审计记录
- 错误码与错误信息

> 支持包**自动脱敏**：密钥、Token、绝对路径被替换；**不包含**项目源码与资源。

### 15.4 崩溃报告

- 崩溃报告默认仅本地保存（`LOCAL_ONLY`）
- **不会自动上传**
- 可手动导出并发送给技术支持

## 16. 故障排查

### 16.1 常见问题

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 插件无法连接后端 | 后端未启动 / 端口被占 / Session 过期 | 检查后端进程、端口 8765、重新连接 |
| 启动提示 schema 过高 | 数据库版本高于产品支持版本 | 使用匹配的新版本产品，或从备份恢复 |
| 模型不可用 | API Key 无效 / 模型未注册 / 网络问题 | 检查 Key、注册模型、检查网络 |
| 更新被拒绝 | 签名无效 / 哈希不符 / 降级 / 未批准 | 检查更新通道与签名，获取有效更新包 |
| 迁移失败 | 备份缺失 / 磁盘不足 / 权限不足 | 查看迁移记录，确保备份存在，按运维手册恢复 |
| Agent 任务卡住 | 等待审批 / 资源锁定 / 预算耗尽 | 检查审批队列、解锁资源、调整预算 |
| 凭据存储不可用 | 系统凭据库未运行 / 无权限 | 启用系统凭据库，或临时使用 `env://` 引用 |

### 16.2 日志位置

- 后端日志：`<数据目录>/logs/`
- 安装日志：安装目录下
- 数据库：`<数据目录>/data/godot_ai_agent.db`

### 16.3 紧急恢复

如果产品无法启动：
1. 找到最近的数据库备份：`<数据目录>/data/backups/`
2. 复制备份为新的数据库文件
3. 使用匹配版本的产品启动
4. 如仍失败，生成支持包联系技术支持

### 17.3 配置关键字段速查

以下为后端真实环境变量（前缀 `GODOT_AI_`，对应 `apps/backend/src/config/settings.py` 的 `Settings` 字段）。安装器附带的 `Start-Backend.cmd` 已自动设置数据目录与 `GODOT_AI_DATABASE_URL`，一般无需手动配置。

```ini
# 网络：仅允许回环地址
GODOT_AI_HOST=127.0.0.1
GODOT_AI_PORT=8765

# 数据与数据库（GODOT_AI_DATABASE_URL 为必填，缺失即拒绝启动）
GODOT_AI_DATA_DIR=<数据目录>/data
GODOT_AI_DATABASE_URL=sqlite+aiosqlite:///<数据目录>/data/godot_ai_agent.db
GODOT_AI_LOG_DIR=<数据目录>/logs

# 运行环境与模型 Provider（none / openai / anthropic / 本地）
GODOT_AI_ENVIRONMENT=development
GODOT_AI_MODEL_PROVIDER=none
```

> API Key、Token 不属于上述环境变量，统一经系统凭据库存储，在配置中以 `cred://` 等引用（见第 12.3 节）。
