# 用户指南（Godot AI Agent Platform 1.0.0）

> 文档目的：指导最终用户安装、首次运行、日常使用、升级、备份与卸载产品。
> 适用范围：Windows 10/11 x86_64 + Godot 4.x；Linux / macOS 见第 9 节支持等级。
> 最后更新：2026-11-27（E12-T13）。

## 1. 产品简介

Godot AI Agent Platform 在 Godot 编辑器旁边运行一个本地后端，通过规划、工具调用、
项目访问控制、变更集与审批、验证与构建发布等能力，辅助完成 Godot 游戏开发任务。

- 产品版本：`1.0.0`（版本域 `product`）
- 游戏制品版本域：`game_artifact`（与产品版本隔离，互不比较）
- 数据库 schema：`000033`
- 默认数据目录（Windows）：`%LOCALAPPDATA%\GodotAIAgent`
- 默认数据目录（Linux）：`$XDG_DATA_HOME/godot-ai-agent`

产品只读写你显式连接的项目目录；AI 生成内容必须经过变更集与审批后才会写入项目。

## 2. 系统要求

| 项 | 最低 | 推荐 |
| --- | --- | --- |
| 操作系统 | Windows 10 x86_64 | Windows 11 x86_64 |
| Godot | 4.4 | 4.5.1 |
| 磁盘 | 2 GB 可用 | 10 GB 可用 |
| 内存 | 8 GB | 16 GB |
| 网络 | 配置在线模型时需要 | 稳定网络 |
| 凭据存储 | 系统凭据库（Windows Credential Manager / macOS Keychain / Secret Service） | 同左 |

安装前请运行兼容性检查：产品会校验系统、架构、Godot 版本、协议版本、
数据库 schema 与凭据存储，未知环境不会被当作通过。

## 3. 安装

1. 关闭正在运行的 Godot 编辑器。
2. 运行 Windows 安装包：`GodotAIAgent-Setup-1.0.0.exe`（位于 `release/installers/windows/`）。Linux / macOS 安装包尚未构建，支持等级见第 9 节。
3. 选择安装目录。安装目录与数据目录必须分离，数据目录不得位于安装目录内部。
4. 安装器执行预检查（组件完整性、目录隔离、写权限、磁盘空间）后才复制文件。
5. 安装完成后启动产品。安装器会记录每一步状态；任一步失败会停止并给出恢复入口。

安装目录默认结构：

```text
<安装目录>/
  backend/            # 本地后端可执行文件
  godot_plugin/       # Godot 插件（addons/godot_ai_agent）
  documentation/      # 本指南与运维手册
  uninstall.exe
```

数据目录默认结构：

```text
<数据目录>/
  config/             # 分层配置
  data/               # SQLite 数据库与备份
  logs/               # 结构化日志
  support-bundles/    # 诊断支持包
```

## 4. 首次运行向导

首次启动会依次引导 12 个步骤：

1. 欢迎与许可协议
2. 选择数据目录（必须与安装目录分离）
3. 初始化数据库（显示 schema 版本）
4. 健康检查（后端、数据库、迁移）
5. 配置凭据存储（系统凭据库；不可用时明确警告，不静默降级）
6. 选择模型 Provider（OpenAI / Anthropic / 本地）
7. 配置 API Key（保存为 `cred://` 引用，界面不回显明文）
8. 选择默认模型（不可用时直接报错，不自动切换）
9. 设置预算（Token / 成本 / 时长上限）
10. 检测 Godot 版本
11. 安装 Godot 插件
12. 连接项目目录

任一步失败可返回上一步；凭据缺失、模型不可用与项目不可写都会阻止继续。

## 5. 在 Godot 中启用插件

1. 打开 Godot 项目，进入 `项目 → 项目设置 → 插件`。
2. 启用 `Godot AI Agent`。
3. 在 `AI Agent` 面板中点击“连接后端”。
4. 后端地址默认 `http://127.0.0.1:8765`，可在面板中修改。
5. 连接成功后状态显示为已认证，并显示 Session 与项目身份。

插件升级由产品管理器执行：先展示当前版本、目标版本与冲突文件。
你本地修改过的文件不会被覆盖；存在冲突时必须人工确认。

## 6. 日常使用

### 6.1 连接项目

- 一个编辑器会话只绑定一个项目；项目身份由 Godot 工程文件确定。
- 切换项目需要新建会话，旧会话不会跨项目复用权限。

### 6.2 与 Agent 协作

1. 在任务面板创建任务，填写目标与验收标准。
2. Agent 读取项目上下文、制定计划并调用受限工具。
3. 只读工具可直接执行；写操作会生成 ChangeSet。
4. 在审批面板查看差异、风险等级与影响范围，批准后才写入。

### 6.3 工具权限

| 风险 | 示例 | 默认行为 |
| --- | --- | --- |
| R0 | 读取配置 | 允许 |
| R1 | 读取项目文件 | 允许（需项目访问权限） |
| R2 | 写入文件 | 需要 ChangeSet |
| R3 | 运行命令 / 导出 | 需要人工审批 |
| R4 | 删除 / 发布 | 需要强审批 |

### 6.4 验证、构建与发布

- 验证中心按静态、结构、资源、运行时、视觉与性能分层执行；没有证据的通过不算通过。
- 构建使用固定 Godot 版本与导出预设，产物不可变；相同内容幂等，不同内容生成新版本。
- 发布候选必须通过冒烟检查并由你显式批准；批准会绑定产物哈希，内容变化后自动失效。

## 7. 配置与凭据

配置分为四层，优先级从低到高：

```text
SYSTEM_DEFAULT < USER_GLOBAL < PROJECT_OVERRIDE < SESSION_OVERRIDE
```

- 安全与隐私关键项受保护：`security.*`、`permissions.*`、
  `privacy.telemetry_default`、`update.require_signature`、
  `update.require_user_approval`、`agent.install_allowed`。
  低优先级配置不能覆盖受保护项。
- API Key、Token 等敏感值只能保存为 `cred://`、`secret://`、`keyring://`、
  `env://` 或 `${ENV_VAR}` 引用；明文会被拒绝。
- 导出配置时会脱敏密钥与绝对路径。

详细规范见 [Secrets 管理规范](../03-development/secrets.md)。

## 8. 升级、回滚与卸载

### 8.1 检查更新

- 更新通道：`DEV`、`BETA`、`STABLE`，默认 `STABLE`。
- 更新清单必须带签名与 SHA-256；签名无效、哈希不符、版本低于当前版本或缺少必要字段时禁止安装。
- 安装前必须由你显式批准；更新不会静默替换正在使用的版本。

### 8.2 数据库迁移

- 升级前会强制创建备份，备份路径写入迁移记录。
- schema 高于产品支持版本时阻止启动（防止降级写入）。
- 迁移失败会进入 `RECOVERY_REQUIRED`，按 [运维手册](../04-operations/runbooks.md) 恢复。

### 8.3 回滚

- 安装失败可回滚到上一个可用版本，用户数据不会被删除。
- 恢复点分为数据库、配置、插件与完整恢复；无法确认的外部状态标记为 `UNKNOWN`，需要人工核实。

### 8.4 卸载

- 卸载默认保留用户数据、项目与日志。
- 卸载不会删除任何 Godot 项目文件。
- 需要清理数据时，请在“隐私与数据”页面单独确认。

## 9. 平台支持等级

| 平台 | 等级 | 说明 |
| --- | --- | --- |
| Windows 10/11 x86_64 | VERIFIED | 完整验证 |
| Linux x86_64 | PARTIAL | 核心功能验证，安装器与桌面集成待验证 |
| macOS x86_64 / arm64 | UNVERIFIED | 可运行但未列入 GA 支持 |
| Godot 4.5.x | VERIFIED | 推荐 |
| Godot 4.4.x | PARTIAL | 兼容但部分编辑器 API 行为不同 |
| Godot ≤ 4.3 | UNSUPPORTED | 拒绝连接 |
| Python 3.14 | VERIFIED | 后端内置运行时 |

## 10. 隐私

- 遥测默认关闭；开启必须显式选择类别（如崩溃报告、使用统计）。
- 上下文预览不包含项目源码、资源、绝对路径与密钥。
- 删除数据仅影响遥测与诊断记录，不触碰项目文件。
- 支持包默认脱敏，导出前需要确认。

## 11. 故障排查

| 现象 | 处理 |
| --- | --- |
| 启动提示 schema 过高 | 使用匹配的新版本产品，或从迁移前备份恢复 |
| 插件连接失败 | 检查后端端口、Session 是否过期、项目访问是否授予 |
| 模型不可用 | 在配置页重新选择已注册且可用的模型，不会自动降级 |
| 更新被拒绝 | 检查签名、哈希、通道与版本；见运维手册“更新失败” |
| 需要技术支持 | 生成支持包：诊断 → 导出支持包（需确认） |

完整处置流程见 [运维手册](../04-operations/runbooks.md) 与产品内错误码目录
（`docs/03-development/errors.md` 登记规范）。
